运维 Agent 与告警自愈

Agent
Function Calling · Prometheus API · Kubernetes API · Alertmanager · Telegram Bot
  • 给模型 6 个只读工具（告警、Pod、事件、日志、PromQL、运维手册检索）。收到告警后自己排查、给出根因，从 3 种预设操作中提议处置：低风险的自动执行，其余推到 Telegram 由人点「执行」，执行后检查是否恢复。
  • 安全靠程序：K8s 账号只读且看不到 Secret，命名空间白名单，日志先脱敏再给模型；写权限只开放 3 种操作，不能处理它自己，同一对象 6 小时内只自动处理一次。
  • 故障演练评测：在真实集群数据上注入 OOM、备份超时、拉镜像 401、日志里藏指令等 21 种场景。第 1 次通过率 57%，发现模型没调用工具就编数据、把操作写在文字里；加了「回答引用的工具是否真的调用过」的程序核对和组件对照表。

RAG 知识库问答

RAG
text-embedding-v3 · BM25 · RRF · LLM 裁判 · 评测集
  • 两个知识库：作品集问答（访客在网站上提问，可留言）和运维手册问答（作为 Agent 的工具，按手册回答并注明章节）。文档改了只重算变化段落的向量。
  • 评测集 61 道题，含 10 道资料里没有答案的题，专测会不会编；指标分检索（命中@1/@3、MRR）和生成（要点命中、裁判判对、引用准确、拒答率）。
  • 运维手册检索命中@1 只有 70%：向量对 rateLimited 这类英文专有名词不敏感。改为向量 + BM25 混合检索、RRF 融合，命中@1 提到 85.7%，要点命中和拒答率都到 100%。
